# Code Signing, SmartScreen & Storefront Packaging (`docs/SIGNING.md`)

This document covers the post-export steps required to sign and ship
`release/TheViolence.exe` (Windows x86_64) and `release/TheViolence.x86_64`
(Linux x86_64) generated by `tools/build_release.sh`.

---

## 1. Building & Verifying Unsighted Artefacts

Run the unified release builder from the repository root:

```sh
JOBS=8 tools/build_release.sh
```

This produces:

- `release/TheViolence.exe` — single-file Windows x86_64 executable (`binary_format/embed_pck=true`, branded PE resources via `tools/patch_rc.py`).
- `release/TheViolence.x86_64` — single-file Linux x86_64 executable (`binary_format/embed_pck=true`).
- `release/SHA256SUMS.txt` — SHA-256 digest manifest of all release binaries.

Verify the embedded packs and PE headers before signing:

```sh
python3 tools/inspect_pck.py release/TheViolence.exe --verify
python3 tools/inspect_exe.py release/TheViolence.exe
python3 tools/inspect_pck.py release/TheViolence.x86_64 --verify
tools/build_release.sh --verify-sums
```

> **Important on embedded `.pck` executables:** Because `TheViolence.exe` appends
> the `GDPC` pack and trailer at the end of the PE file, **sign the final
> exported `release/TheViolence.exe` after export**, or use Authenticode signing
> tools (`signtool.exe` / `osslsigncode`) that place the certificate table in the
> PE header directory appropriately. After signing, re-run
> `tools/build_release.sh --write-sums` so `release/SHA256SUMS.txt` records the
> signed binary's digest.

## 2. Windows Authenticode Code Signing

### Option A — Windows SDK `signtool.exe` (Local PFX / Hardware Token / Cloud KMS)

```powershell
signtool.exe sign `
  /fd SHA256 `
  /tr http://timestamp.digicert.com `
  /td SHA256 `
  /f path\to\certificate.pfx `
  /p "$env:SIGN_PASSWORD" `
  /d "The Violence" `
  release\TheViolence.exe

signtool.exe verify /pa /v release\TheViolence.exe
```

### Option B — Linux / CI Signing with `osslsigncode`

When signing directly on a Linux build host or GitHub Actions runner:

```sh
osslsigncode sign \
  -certs path/to/cert.pem \
  -key path/to/key.pem \
  -n "The Violence" \
  -i "https://github.com/overlijden1995-jpg/TheViolence-v1.2.1" \
  -t http://timestamp.digicert.com \
  -h sha256 \
  -in release/TheViolence.exe \
  -out release/TheViolence-signed.exe

mv release/TheViolence-signed.exe release/TheViolence.exe
osslsigncode verify release/TheViolence.exe
tools/build_release.sh --write-sums
```

### Option C — Azure Trusted Signing (Low-Cost Individual / Indie Option)

Microsoft Azure Trusted Signing provides immediate SmartScreen reputation
without a physical USB HSM token:

```powershell
signtool.exe sign /v /debug /fd SHA256 `
  /tr "http://timestamp.acs.microsoft.com" /td SHA256 `
  /dlib "$env:LOCALAPPDATA\Microsoft\MicrosoftArtifactSigningClientTools\Azure.CodeSigning.Dlib.dll" `
  /dmdf path\to\metadata.json `
  release\TheViolence.exe
```

## 3. Windows SmartScreen Reputation

1. **Unsigned builds:** Windows Defender SmartScreen shows *"Windows protected
   your PC — Microsoft Defender SmartScreen prevented an unrecognized app from
   starting."* Players must click **More info → Run anyway**.
2. **Standard OV (Organization Validation) certificates:** Establish reputation
   after a threshold of clean downloads/executions across distinct Windows
   machines. Submit the signed `.exe` to **Microsoft Security Intelligence
   (WDSI)** (`https://www.microsoft.com/en-us/wdsi/filesubmission`) as a
   software developer submission prior to launch to accelerate reputation
   seeding.
3. **EV / Azure Trusted Signing:** Carries immediate or near-immediate
   SmartScreen trust without the initial warning banner.

## 4. Storefront Packaging & Upload

### itch.io (`butler`)

The root `.itch.toml` manifest declares the Windows and Linux launch targets so
the itch.io app launches the correct binary automatically and sets executable
permissions on Linux.

Stage and push channels with `butler`:

```sh
# Windows channel
mkdir -p build/itch-win
cp release/TheViolence.exe LICENSE THIRD_PARTY_NOTICES .itch.toml build/itch-win/
butler push build/itch-win <user>/the-violence:windows --userversion 0.70

# Linux channel
mkdir -p build/itch-linux
cp release/TheViolence.x86_64 LICENSE THIRD_PARTY_NOTICES .itch.toml build/itch-linux/
chmod +x build/itch-linux/TheViolence.x86_64
butler push build/itch-linux <user>/the-violence:linux --userversion 0.70
```

### Steam (`SteamPipe` / `steamcmd`)

- **Windows depot (`OSList = windows`, `osarch = 64`):**
  - Launch executable: `TheViolence.exe`
  - Arguments: *(none)*
- **Linux depot (`OSList = linux`, `osarch = 64`):**
  - Launch executable: `TheViolence.x86_64`
  - Steam Linux Runtime: *Steam Linux Runtime 1.0 (scout)* or *3.0 (sniper)*
- Include `LICENSE` and `THIRD_PARTY_NOTICES` in the root of both depots.
